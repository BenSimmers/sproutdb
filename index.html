SproutDB

A tiny database that grows with your prototype.

SproutDB is a typed, in-memory TypeScript database with Mongo-style queries. Use it as a library, or run it as a mock REST server with a live dashboard for your frontend and tests.

Get started View on GitHub
$ npm install sproutdb 
import { create, table, persist } from 'sproutdb';
import { localStorageAdapter } from 'sproutdb';

const db = create({
  users: table<User>({ key: 'id' }),
});

persist(db, localStorageAdapter('my-app'));

db.users.insert({ id: 1, name: 'Alice', age: 30 });

db.users.find({
  where: {
    age: { $gte: 18 },
    'address.city': 'Paris',
  },
  sort: { name: 'asc' },
  limit: 10,
});
$ npx sproutdb --seed sprout.json --persist data.json

Server running on port http://localhost:3000
Dashboard: http://localhost:3000/dashboard/

$ curl 'localhost:3000/tables/users?age[$gte]=18&_sort=-age'
[{ "id": 1, "name": "Alice", "age": 30 }]

$ curl -X POST localhost:3000/tables/users \
    -H 'Content-Type: application/json' \
    -d '{"name": "Bob", "age": 25}'
{ "name": "Bob", "age": 25, "id": 2 }
import request from 'supertest';
import { createServer } from 'sproutdb/server';

test('loads a user', async () => {
  // A fresh, isolated server for every test
  const { app } = createServer({
    seed: { users: [{ id: 1, name: 'Alice' }] },
  });

  const res = await request(app).get('/tables/users/1');

  expect(res.body.name).toBe('Alice');
});
Features

Everything a prototype needs. Nothing it doesn't.

The core library has zero runtime dependencies and runs anywhere JavaScript does: Node, browsers and edge runtimes.

Mongo-style queries

Comparisons, sets, regex, $and/$or/$not, nested fields, sorting, pagination and projection.

Typed & validated

Fully typed tables, plus runtime validation with Zod or any validator that has a safeParse method.

Primary keys

Unique keys with get and upsert. Duplicates are rejected before anything changes.

Transactions & snapshots

Roll every table back if something throws, or save and restore the whole database in one call.

Pluggable persistence

Keep data in memory, localStorage or a JSON file, or write your own adapter in a few lines.

Change subscriptions

React to every insert, update and delete, whether that's in a UI, a cache or over server-sent events.

Mock REST server

npx sproutdb gives you REST routes, query-string filters, automatic ids and seed data. No config needed.

Test-friendly

An isolated server per test, reset and snapshot endpoints, and direct access to the database for setup.

Get started

One package, three ways to use it.

Start with a library call, move to a mock backend when your frontend needs one, and use the same server in your tests.

1In your code

A typed, in-memory store for scripts, prototypes and browser apps.

const db = create({
  todos: table<Todo>({ key: 'id' }),
});

db.todos.insert({ id: 1, done: false });
db.todos.find({ where: { done: false } });

2As a mock backend

A REST API and dashboard for your frontend, seeded from JSON.

$ npx sproutdb --seed sprout.json

GET    /tables/todos?done=false
POST   /tables/todos
PATCH  /tables/todos/1
DELETE /tables/todos/1

3In your tests

A fresh server per test, with no ports and no cleanup.

const { app, db } = createServer();

db.todos.insert({ id: 2, done: true });
await request(app).get('/tables/todos');
Dashboard

See your data change as it happens.

Reference

A small API you can learn in minutes.

The highlights are below. The README has everything.

Table methods

insert(record) Add a record; returns the stored copy
find(query?) Filter, sort, paginate and select fields
findOne(query?) The first match, or undefined
count(query?) Number of matching records
get(key) / upsert(record) Look up or replace by primary key
update({ where }, changes) Merge changes; validated, all or nothing
delete({ where }) Remove matches; returns the count
subscribe(listener) Listen for every change

Query operators

{ name: 'Alice' } Equality, including deep equality for objects, arrays and dates
$gt $gte $lt $lte Comparisons
$eq $ne Equal / not equal
$in $nin In / not in a list
$regex Pattern match
$exists Field present or missing
$and $or $not Combine and negate conditions
'address.city' Query nested fields with dot paths

Database helpers

transaction(db, fn) Roll back every table if fn throws
snapshot(db) Copy all data to a JSON-safe object
restore(db, snapshot) Put a snapshot back
persist(db, adapter) Load saved data, then save every change

REST endpoints

GET/tables/:table List, with query-string filters
POST/tables/:table Create (an id is assigned if missing)
PATCH/tables/:table/:id Merge fields into a record
GET/tables/:table/events Live changes (server-sent events)
POST/reset Back to the seed data
